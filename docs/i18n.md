# Internationalization (i18n)

AnyQuery ships a lightweight, dependency-free i18n layer for the web UI.

## Supported locales

| Code | Language | Direction |
| --- | --- | --- |
| `en` | English | LTR |
| `zh-CN` | 简体中文 | LTR |
| `es` | Español | LTR |
| `hi` | हिन्दी | LTR |
| `ar` | العربية | RTL |
| `pt` | Português | LTR |
| `ru` | Русский | LTR |
| `ja` | 日本語 | LTR |
| `de` | Deutsch | LTR |
| `fr` | Français | LTR |

## Behavior

- On first visit the browser language is detected, then falls back to English.
- The choice is stored in `localStorage` under `aq-locale`.
- `<html lang>` and `<html dir>` are updated automatically; Arabic uses RTL.
- The language picker is available on the login screen and under the user menu → **Language**.
- Dates, relative times and numbers use the active locale via `Intl`.
- Missing translations fall back to the English source string.

## Coverage

Translated today: application shell and navigation, login, overview, query studio actions, results states and common feedback such as loading/copy/error messages. Administrative pages (data source forms, team management, settings) currently use the English fallback; the i18n framework is ready for those strings to be moved into the same dictionaries.

Backend error messages and audit records remain English. Query SQL is never translated.

## Adding a locale

1. Add the locale metadata and dictionary in `frontend/src/i18n/index.tsx`.
2. Reuse keys that exist in the English dictionary; keep `{placeholders}` unchanged.
3. Run `pnpm build` and verify both LTR and RTL layouts.
